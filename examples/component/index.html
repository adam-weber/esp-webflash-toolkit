<esp-flasher>

Flash ESP32 firmware from any web page.

A drop-in web component with Shadow DOM. Add a script tag and an HTML element to any page — get a working firmware flasher with USB serial, NVS configuration, and guided error recovery. No build step required.

Installation

Load the component from a CDN. It self-registers the <esp-flasher> custom element — no imports or initialization needed.

html
<script src="https://cdn.jsdelivr.net/npm/esp-webflash-toolkit@latest/dist/esp-flasher-component.min.js"></script>

Compact mode

The default mode renders a single button. Clicking it opens the full flash UI in a modal overlay with a blurred backdrop. Ideal for embedding in existing pages where the flasher shouldn't dominate the layout.

The modal handles everything: device connection, configuration fields, progress, error recovery, and post-flash instructions. It dismisses on backdrop click or the close button.

html
<esp-flasher
  firmware="https://github.com/user/repo/releases/latest/download/firmware.bin"
  chip="esp32s3"
  fields="wifi"
></esp-flasher>

Full mode

Set mode="full" to render the flash UI inline as a card. Use this when the flasher is the main content on the page, or when you want the UI visible without requiring a click.

The card centers itself at 400px max-width. All fields defined in the fields attribute are rendered as form inputs — the wifi preset expands to SSID and password fields, and device_name adds a text input.

html
<esp-flasher
  firmware="https://github.com/user/repo/releases/latest/download/firmware.bin"
  chip="esp32"
  fields="wifi,device_name"
  mode="full"
></esp-flasher>

Config URL

For projects with multiple firmware variants, custom branding, or post-flash setup instructions, point the component at a flash-config.json file. The component fetches it, normalizes the format (v1 configs are auto-upgraded), and renders a variant dropdown when multiple variants are defined.

Config files without a version field are treated as v1. See the docs for the full v2 schema with branding, variants, and post-flash steps.

html
<esp-flasher
  config="https://raw.githubusercontent.com/user/repo/main/flash-config.json"
  mode="full"
></esp-flasher>

Events

The component dispatches Custom Events with composed: true, so they cross the Shadow DOM boundary. Listen directly on the element.

javascript
const el = document.querySelector('esp-flasher')

el.addEventListener('esp-flasher:connected', (e) => {
  console.log('Chip:', e.detail.chipType)
  console.log('MAC:', e.detail.macAddr)
})

el.addEventListener('esp-flasher:complete', () => {
  console.log('Done!')
})

el.addEventListener('esp-flasher:error', (e) => {
  console.log('Error:', e.detail.message)
})
EventDetailDescription
esp-flasher:connected{ chipType, macAddr }Device connected and identified
esp-flasher:complete{}Flash finished successfully
esp-flasher:error{ message }An error occurred during the process

css
esp-flasher {

  --c-accent-hover: #4f46e5;
  --c-surface: #ffffff;
  --c-text: #09090b;
  --c-border: #e4e4e7;
}

When loading config via URL, the branding.primaryColor field automatically maps to --c-accent, and branding.theme: "dark" flips all color variables to a dark palette.

Programmatic access

The component exposes its internal ESPFlasher instance on the .flasher property. Use it to set config values, read state, or control the flash process from JavaScript.

javascript
const el = document.querySelector('esp-flasher')

// Set config values before or during use
el.flasher.setConfig({ wifi_ssid: 'MyNetwork', wifi_pass: 'secret' })

// Read current config state
const config = el.flasher.getConfig()

// Get the field schema
const schema = el.flasher.getSchema()

Reading config in firmware

When you flash with fields="wifi,device_name", the component writes those values to an NVS (Non-Volatile Storage) partition on the device. Your firmware reads them back using standard ESP-IDF APIs — no special library needed.

All values are stored in a namespace called "config" at partition offset 0x9000. The NVS keys match the field names exactly:

Field presetNVS keys writtenType
wifiwifi_ssid, wifi_passstring
mqttmqtt_host, mqtt_user, mqtt_passstring
device_namedevice_namestring

Here's how to read them in your firmware:

Arduino

cpp
#include <Preferences.h>
#include <WiFi.h>

Preferences prefs;

void setup() {
  Serial.begin(115200);

  // Open the "config" namespace (read-only)
  prefs.begin("config", true);

  // Read the values that were flashed
  String ssid = prefs.getString("wifi_ssid", "");
  String pass = prefs.getString("wifi_pass", "");
  String name = prefs.getString("device_name", "esp-device");

  prefs.end();

  // Use them
  Serial.printf("Connecting %s to %s\n", name.c_str(), ssid.c_str());
  WiFi.begin(ssid.c_str(), pass.c_str());
}

ESP-IDF (C)

c
#include "nvs_flash.h"
#include "nvs.h"

void read_config() {
    nvs_flash_init();

    nvs_handle_t handle;
    nvs_open("config", NVS_READONLY, &handle);

    char ssid[33], pass[65], name[64];
    size_t len;

    len = sizeof(ssid);
    nvs_get_str(handle, "wifi_ssid", ssid, &len);

    len = sizeof(pass);
    nvs_get_str(handle, "wifi_pass", pass, &len);

    len = sizeof(name);
    nvs_get_str(handle, "device_name", name, &len);

    nvs_close(handle);

    printf("WiFi: %s, Device: %s\n", ssid, name);
}

Rust (esp-idf-svc)

rust
use esp_idf_svc::nvs::*;

fn read_config() -> Result<(), EspError> {
    let nvs = EspDefaultNvsPartition::take()?;
    let ns = EspNvs::new(nvs, "config", true)?;

    let mut buf = [0u8; 128];

    let ssid = ns.get_str("wifi_ssid", &mut buf)?;
    let pass = ns.get_str("wifi_pass", &mut buf)?;
    let name = ns.get_str("device_name", &mut buf)?;

    Ok(())
}

Key things to know:

ConceptValueNotes
Namespace"config"All fields are stored under this NVS namespace
Partition offset0x9000Must match your partition table's NVS offset
Partition size0x6000 (24KB)Default size, configurable via config
Key length15 chars maxNVS keys are case-sensitive, alphanumeric + underscore
FormatESP-IDF NVSStandard binary format — no custom parser needed

The NVS partition is written alongside the firmware in a single flash operation. Your firmware just needs to call nvs_flash_init() (or Preferences.begin() in Arduino) and read the keys — nothing else to configure.
